# Worked patterns from the supplied workbooks

These examples apply the same method to different business models. Example URL paths are proposals and evidence requirements. Workbook cells, linked drafts, old prices, search volumes, third-party metrics, positions and operations status are historical inputs. Verify live facts before using them publicly.

## Scaxa: B2B equipment catalogue and rental website

**Source context.** An equipment supplier helps construction buyers select the correct scaffolding system and request rental or purchase. **Central entity.** Construction scaffolding. **Central intent.** Specify a system or component for a job and obtain the appropriate solution or quote.

| Role | Example task | Page and its job | Proof and link |
| --- | --- | --- | --- |
| Core service | Rent scaffolding for a project in a genuinely served market | `/scaffolding-rental/` with service, supported systems and quote flow | Approved service area, terms and availability. Link into relevant system inventory and the quote flow. |
| Core system or category | Select a scaffold system such as Cuplock or frame | Relevant system collection with use cases and compatible components | Manufacturer catalogue, compatibility rules and actual stock. Link to approved product pages. |
| Core product | Evaluate an exact item such as Aluminium Beam S-150 | Existing product route with quote or order path | Manufacturer data for dimensions, materials, compatible system, limits and imagery. Leave unconfirmed attributes out. Link back to the system and relevant parts. |
| Outer education | Learn what scaffolding is or compare its types | Definition hub and a distinct types comparison if live intent and evidence justify both | Definitions, diagrams and technical or safety sources as applicable. Link into the right systems and rental option from the relevant sections. |
| Specialized application | Choose scaffolding for industrial maintenance or an event | Page or section based on actual service and distinct requirements | Real job constraints, scope and approved proof. Defer cloned pages. |
| Adjacent information | Check components or local safety requirements | Components hub or authority-reviewed jurisdiction page if useful | Verify rules and technical claims for the stated market. A US reference cannot substantiate a UAE-specific rule. |

**What to transfer.** The workbook links a processed map (topic, title, query, URL, article and image) to a product table (URL, question set, content brief) and heading-level briefs (heading level, purpose, noun phrases, studies). Turn each product question into a verified specification, compatibility field or answered purchase objection. Keep education, rental, sales and use-case intents distinct. Review overlaps in adjacent terms such as rolling/mobile and type/system names. Filter the keyword export for ambiguous strings such as scaffolding in education, psychology or gaming. Leave empty or incomplete planning cells in the review queue.

**Apply elsewhere.** The same shape fits spare parts, software integrations, electronics, construction services or accessories. Product/feature → category/system → use-case guide works only where the relationship and user journey are real.

## Dubai City Tourism: destination publisher and referral site

**Source context.** Help visitors plan an actual visit, with a booking or referral only where a real offer exists. **Central entity.** Visitor destinations in the covered geography. **Central intent.** Decide where and when to go and understand the logistics.

| Page candidate | What to do | Why |
| --- | --- | --- |
| Riverland Dubai destination + “Dubai Riverland Entrance Fee” | Inspect live intent before creating two pages. Start with an accessible admission section on the destination page if the same page can answer both. Split only if the fee task has distinct evidence and scope. | The content-plan tab lists both requests and the destination brief already contains admission details. Avoid two thin versions of the same answer. |
| Hatta Dam destination | Cover location, routes, opening status, permitted activities and accessibility in the order visitors need them. Include maps or their source where they help. | The destination brief mixes broad and specific visit questions. Confirm conditions by operator and authority, especially fees and permitted activity. |
| Louvre Abu Dhabi dress code | Verify venue policies and whether the question is best as a section on an existing venue guide. Review Abu Dhabi's place in the site's legitimate geographic scope. | The sample headings include definitive claims and repeat a question. One supported answer with current conditions has more utility. |
| Snoopy Island entry fee | Separate public access, operator-specific fees and activities where relevant. Give dated prices only with exact source and conditions. | The workbook mixes island, beach, hotel and activity questions. Entity and operator disambiguation prevents publishing the wrong fee. |
| Multi-destination comparison | Link from genuinely distinct attraction pages into a verified itinerary, family guide or regional hub. | The usefulness of the hub depends on audience task, travel connections and accurate boundaries. |

**What to transfer.** The workbook uses a topic/owner/status plan, an authority checklist, competitor and outreach lists, and named page briefs with heading level, methodology, competition, queries, entities and attributes. Implement the same handoff and checkpoints. Treat “Completed” or “Pass” as historical workflow status. Verify live accessibility/canonical, robots, sitemap, mobile utility, ownership and tool evidence before assigning current status. Keep platform plugins and decorative features conditional. Qualify backlink candidates for relevance, earned relationship, real audience and disclosure. Unrelated profiles and placements provide no useful outreach target for this work.

**Apply elsewhere.** For venues, jobs, docs versions or directories build policies for current, closed, replaced and unverified records. Route regional pages based on verified inventory and useful local detail. A CSV workflow can map `place → venue → attribute → fetch date → page action`.

## SaaS pattern from Semantic Youtube Notes

Start with an identity and product audit: stable naming, product category, buyer, contracting or support details, actual features, use cases, versions and evidence. Use sales/support notes, customer language, public forum discussions and relevant competitors to find information gaps. Public discussion is listening evidence. Any participation should be transparent and helpful. Treat vendor-owned profiles and genuinely independent reviews as different evidence. Plan around workflow task → feature/use-case → documented implementation → demo or trial. Measure activation or retention alongside signup when data is available.
