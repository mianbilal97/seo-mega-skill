# Semantic architecture, briefs and content configuration

## Turn ideas into observable decisions

| Concept from the course and notes | Apply it to real work |
| --- | --- |
| Source context + central entity → central search intent | Write a scope sentence with audience, task, central entity, offered role and relevant market. Use it to qualify coverage, information and the primary conversion. An equipment supplier and an educational publisher make different pages about the same equipment. |
| Taxonomy and ontology | Give each entity a type and place in the hierarchy. Record relationships such as `component belongs to system`, `service covers area` or `tool converts unit`. Keep the claim's source and conditions with each relationship. |
| Relevant vs responsive | A relevant page matches the task and context. A responsive passage or interaction gives the answer or completes the task. Check both an on-topic title and whether a visitor can get a specific answer, use the calculator or take the next step. |
| Contextual domain and vector | From the many plausible meanings choose the one that fits this audience and decision. Document the sequence of meaningful headings or interactive sections as the **contextual vector**. Read it without body text and check whether it still matches the page's primary job. |
| Contextual flow and hierarchy | Put the highest-priority answer or functional action where it is needed. Group questions by parent task and place dependent qualifiers under the corresponding heading. Distinguish site-wide vocabulary, title patterns and navigation from sentence-level phrasing decisions. |
| Main and supplementary content | Main content handles this URL's primary job. Supplementary content resolves related needs or creates a meaningful path to another page. Where relevant use a transition section or grouping question to mark the **contextual border**. Keep the primary task prominent. |
| Contextual bridges and neighborhood content | Establish a reason for moving between pages. Example: a rental page links from system selection to a compatible parts catalogue. Align shared facts even where a hyperlink is unnecessary. Add crawlable links where they make the next task easier. |
| Entity–attribute–value and triples | Record `entity + attribute + value` or `subject + relationship + object`, with proof, scope, version, units and expiry where relevant. Keep one approved record for shared claims. This is an editorial data model and can inform appropriate markup. |
| Vastness, depth and momentum | Plan how broad to go, how detailed the highest-value pages should be and how quickly a team can maintain the material. Prioritize a coherent pilot cluster if resources are limited. Use seasonality and review capacity to schedule releases. |
| Topical coverage and historical data | Track coverage of high-value tasks and actual cohort performance over time. Expect interpretation and results to evolve. Treat the practitioner's topical-authority model as planning vocabulary. Do not claim a known platform score, timeline, ranking state or formula. |
| Content configuration | When audience needs, the offer, SERPs or source facts change, recheck sections, link edges and cluster borders. Update maintained URLs where suitable. Record what changed and measure the affected cohort. |

## Make a section brief executable

For each H2/H3, UI module or answer slot specify:

1. The question, action or decision being served and the entity/attributes it owns.
2. The first complete answer or action. For a short factual question place the condition next to the answer. For a complex question lead with the decision and apply a sequence such as answer → criteria → evidence → exception → next step.
3. The most useful format: definition, list, steps, worked example, comparison table, visual, data, form, product interaction or tool. Put the most important distinctions in explicit labels and values.
4. Approved claim IDs and sources with the necessary unit, locale, population, date, version or compatibility. If evidence is missing note what to verify and who can supply it.
5. Supporting terms, synonyms or examples that clarify the concept. Use short clear subject and verb and avoid copying headings across pages that serve different tasks.
6. Where appropriate add the parent or destination link from the relevant passage. Name the destination's purpose, avoid repeated vague or forced exact-match anchors, and check mobile visibility and destination behavior.

Audit priority pages by reading the title, first screen, heading order, anchor text and CTA together. Check that the intro reflects the actual useful sections and leaves room for the primary experience. Short content can satisfy a narrow task. Long content that repeats generic information can still leave the task unresolved.

## Evidence and link design

- Compare what users can actually do or learn on comparable pages. If the accessible competition matches all basic attributes, find a real evidence improvement such as a verified cost breakdown, compatibility matrix, original measurement or working interaction. Score the evidence gap alongside coverage and task fit.
- Use original data, guides or tools as potential link-earning assets. Build a path from each one into closely related supporting or commercial content only when the reader benefits. Record both published and missing targets. No inferred PageRank weight or ranking lift is required to justify a useful link.
- Check click paths such as `organic landing → product fit → quote → accepted lead`. If available diagnose conversion friction by entry template, device and event. A short successful session is possible on a definition or single-use tool. Do not interpret bounce rate, time or raw click paths as confirmed ranking inputs.
- Place functional navigation and breadcrumbs with the actual hierarchy. Use visually clear semantic headings. For useful visuals record subject, purpose, source/rights, caption as needed and accessible alt text. Decorative images can use empty alt. Prefer actual screenshots, product photos or diagrams of the verified action.
